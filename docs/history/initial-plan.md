# saju-kit 계획


사주 기능을 다른 프로젝트(영끌각 등)에서 불러 쓰기 위한 독립 모듈. 만세력 계산(core)을 바닥에 두고 그 위에 기능(택일, 이사운, 이후 연애운·총운)을 모듈로 얹는다.

> 레포 이름 `saju-kit`은 임시. 바꿔도 이 문서 내용은 그대로 유효.

## 1. 목표 / 비목표

**목표**
- 브라우저에서 서버 없이 돌아가는 순수 JS 모듈 (생년월일 등 개인정보를 서버로 보내지 않음)
- 빌드 없는 정적 사이트(영끌각)에 파일 하나 복사해서 붙일 수 있는 배포물
- 기능은 "점수 + 이유 키 + 날짜" 같은 구조화된 데이터만 반환. 화면 문구는 별도 JSON 표로 분리
- 1차 범위: **core(만세력) + 일반 택일(손 없는 날) + 개인 택일 + 이사운**

**비목표 (지금은 안 함)**
- 연애운, 총운 등 나머지 기능 (3번째 기능을 붙일 때 core API를 검증하면서 추가)
- 요청마다 LLM 호출, 서버 API, 계정/저장
- UI 컴포넌트 (소비처가 각자 그림. 필요하면 나중에 별도 패키지)

## 2. 소비처

| 소비처 | 연동 방식 |
|---|---|
| 영끌각 (rent-or-buy-kr) | `dist/saju-kit.js` 단일 파일을 `site/`에 복사(vendoring). `?v=해시` 캐시 방식과 맞음. 외부 CDN 의존 안 함 |
| Saju Web 등 다른 프로젝트 | ESM import (git 태그 버전 고정) |

영끌각 쪽 규칙: 화면에 전문 용어 금지, 계산기 결과(막대·판정 문구)와 사주는 완전 분리, 한국어판에만 노출.

## 3. 구조

```
saju-kit/
  src/
    core/
      calendar.js     양력↔음력, 절기 시각 조회
      pillars.js      연·월·일·시주 계산, 일진
      luck.js         대운·세운
    features/
      taekil.js       일반 택일(손 없는 날), 개인 택일
      move.js         이사운
      (이후) love.js, overall.js
    data/
      solar-terms.json   절기 시각 표 (1900~2100, 분 단위)
      lunar.json         음력 변환 표 (또는 계산식)
      text/ko.json       해석 문구 (이유 키 → 문장)
  test/
    fixtures/            공인 만세력과 대조한 기준값
    core.test.mjs
    taekil.test.mjs
    move.test.mjs
  scripts/
    build-data.py        절기·음력 표 생성/검증
  dist/
    saju-kit.js          단일 파일 배포물
  PLAN.md
```

규칙
- core는 의존성 0, 순수 함수. features는 core만 import.
- 기능 모듈은 서로 import하지 않음.
- 문구(`text/ko.json`)는 코드와 분리 → 문구만 고치거나 영어판을 붙일 수 있게.

## 4. API 스케치 (확정 아님, M1에서 다듬음)

```js
import { getSaju, dayPillar, isSonEopNeunNal, pickDates, moveFortune } from 'saju-kit';

// core
const saju = getSaju({
  y: 1997, m: 6, d: 28, hh: 8, mm: 30,
  calendar: 'solar',            // 'solar' | 'lunar'
  options: { zasi: 'joja', tzCorrection: true },
});
// → { pillars: { year, month, day, hour }, luck: {...} }

dayPillar(new Date('2027-01-10'));       // 일진
isSonEopNeunNal(new Date('2027-01-10')); // 음력 9·10·19·20·29·30일 여부

// features
pickDates({ purpose: 'move', from, to, saju /* 선택 */ });
// → [{ date, score: 0~100, flags: ['sonEopNeun'], reasons: ['son_free', 'day_clash_me'] }]

moveFortune({ saju, year: 2027 });
// → { score, reasons: ['...'] }

// 문구는 별도
import ko from 'saju-kit/text/ko.json';
```

원칙: 반환값에 화면 문구를 넣지 않는다. `reasons`는 키, 문장은 `text/ko.json`.

## 5. 먼저 정해야 할 계산 정책 (문서로 못 박고 옵션화)

만세력 프로그램마다 다르게 나오는 부분이라 틀리기 쉽다. 기본값을 정하고 `options`로 열어 둔다.

1. **절기 경계**: 입춘 기준 연주 전환, 각 절입 시각(분 단위)으로 월주 전환
2. **시간 보정**: 한국 표준시(동경 135°)와 실제 경도 차이로 약 30분 보정 여부
3. **과거 서머타임**: 한국 서머타임 시행 기간(1948~1960, 1987~1988) 보정 여부
4. **자시 처리**: 야자시 / 조자시 중 기본값
5. **음력 윤달** 처리
6. **일진 기준**: 일주 기준 날짜, 자정 경계

## 6. 기능 범위

### 6-1. 일반 택일 (개인정보 불필요)
- 손 없는 날: 음력 9·10·19·20·29·30일
- 날짜 범위를 주면 후보 날짜 + 플래그 반환
- 영끌각 SEO 용도(검색 "이사 손 없는 날")로 개인정보 없는 페이지를 만들 수 있음

### 6-2. 개인 택일
- 입력: 사주 + 날짜 범위
- 본인 일주와 충 등이 걸리는 날 제외/감점
- 판단 규칙을 표(JSON)로 정리해서 근거를 `reasons` 키로 반환

### 6-3. 이사운
- 입력: 사주 + 연도(세운 기준)
- 출력: 점수 + 이유 키 + 한 줄 요약용 키
- 해석 기준은 사주 공부 내용 기반으로 규칙표를 직접 작성 (가장 손이 많이 가는 부분)

## 7. 검증

- **기준값**: 공인 만세력 값과 대조한 fixture. 절기·음력은 한국천문연구원(KASI) 음양력 정보(공공데이터포털)로 교차 확인 (API 제공 범위는 구현 시 확인)
- **경계 케이스**: 입춘 전후 몇 분, 절입 시각 전후, 자시(23:00~01:00), 윤달, 서머타임 기간, 음력 29/30일
- 상명 본인 사주를 fixture 하나로 포함 (1997-06-28 08:30)
- 테스트는 영끌각과 같은 방식: `node --test test/*.test.mjs`, CI에서 push마다 실행
- 해석 규칙은 "정답"이 없으므로 테스트는 계산(만세력)에만 엄격하게, 규칙표는 스냅샷으로

## 8. 배포

- `dist/saju-kit.js`: 번들러 없이 소스를 이어 붙이거나 최소한의 번들(esbuild)로 단일 파일 생성
- 버전은 git 태그(`v0.1.0` …). 소비처는 태그를 지정해 복사
- 영끌각 연동: `site/`에 복사 → `build_pages.py`가 `?v=해시` 부여 (기존 규칙 그대로)

## 9. 마일스톤

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M0 | 레포 생성, 이 문서 정리, **Saju Web에 기존 만세력 코드가 있는지 조사** | 있으면 그 코드를 core 출발점으로 확정 |
| M1 | core: 절기·음력 표 + 4주 + 일진 + 대운/세운 | fixture 전부 통과, 정책 6개 문서화 |
| M2 | 일반 택일(손 없는 날) + `dist` 빌드 | 영끌각에 붙여 날짜 목록 출력 확인 |
| M3 | 개인 택일 + 이사운 + `text/ko.json` | 규칙표 리뷰 후 확정 |
| M4 | 영끌각 연동 (`/saju/` 별도 페이지, 계산기 결과엔 링크만) | 처리방침·FAQ 문구 수정 포함 |
| M5 | 연애운 또는 총운 1개 추가 | core API를 바꾸지 않고 추가 가능하면 구조 검증 완료 |

## 10. 위험 / 주의

- **계산 오류**: 절기·시간 보정 오류는 눈에 안 띄고 신뢰를 깎음 → 검증 단계를 M1에서 끝낸다
- **해석 책임**: 집·이사처럼 금액이 큰 결정이라 "재미로 보는 참고" 표기를 필수로. 영끌각 계산 결과와 섞지 않음
- **개인정보**: 서버 전송 없음, 저장 없음(localStorage 쓰더라도 선택). 영끌각 개인정보 처리방침에 반영
- **라이선스**: 외부 라이브러리(예: lunar-javascript 류)를 쓰면 라이선스 확인. 직접 구현하면 절기 표 생성 근거를 기록
- **과설계**: 기능 3개 이상 붙이기 전에는 플러그인 시스템 같은 추상화 만들지 않음

## 11. 열린 질문

1. Saju Web에 만세력 계산 코드가 이미 있는가? (있으면 M1 대폭 단축)
2. 레포 공개 여부 (private로 시작 권장, 라이선스 정리 후 공개 판단)
3. 자시·시간 보정의 기본 정책 (상명 본인 사주 풀이 때 쓰는 기준에 맞추는 게 자연스러움)
4. 타입스크립트 사용 여부 (영끌각은 순수 JS. 일단 JS + JSDoc 권장)
