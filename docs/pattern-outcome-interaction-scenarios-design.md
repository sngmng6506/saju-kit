This development-only diagnostic evaluates named properties of the shared
force-basis abstraction, not actual action compatibility. The dependency
graph supplies the visible action inventory; chart-wide DNF profiles
supply formulas. Every query sees the same fixed/unknown primitive values.

- Control query: weak componentwise dominance and at least one strict axis.
- Generation query: any substantial source root or local rooted incoming
  generation basis. It does not imply the full generation screen,
  recipient capacity, discharge, or benefit.
- Report exact counts and witness assignments for each pair's four Boolean
  combinations. An individually possible pair with zero joint witnesses
  is incompatible only in this abstraction.
- A single action's control query must agree with the earlier pair-local
  completion envelope. The chart-wide count may differ because other
  queries introduce variables.
- Generic explicit scenario constraints require provenance and are
  conjunctively enforced. Production diagnostic supplies no such extra
  constraints: observed overlap is not a physical exclusion rule.
- No probability interpretation of assignment counts. No vacuous
  invariance on empty admissible space. Partial hours and resource limits
  produce no compatibility verdict.
- Maximum 16 referenced unknowns, 64 queries, 12,000 formula nodes and
  bounded enumeration work. Unavailable results are explicit; no sampling.
- Pairwise possibility does not imply all-query joint possibility.
  P2-D (v2) includes exact whole-set analysis of these same basis queries.
  It does not yet combine all signed joint proof targets into one admissible

## P2-D exact set frontier

The optional `includeSets` mode collects truth masks and one witness per
mask during the original scenario enumeration. No independent completion
or new evidence is introduced. For a selected subset S its support
count is the sum of counts of all truth masks containing S.
A superset zeta transform evaluates all subset counts in O(n*2^n)
time and O(2^n) numeric storage after enumeration.

A feasible set is inclusion-maximal iff every one-element extension
is infeasible. An infeasible set is inclusion-minimal iff every
one-element removal is feasible. Singleton cores are retained; they
are not evidence of competition. Every maximal feasible set carries
a witness, and minimal cores report exact support counts after each
one-element removal. These frontiers describe basis properties only;
neither maximum cardinality nor a preferred action set is inferred.

Set analysis is bounded to 16 queries and 4,096 combined frontier
entries. If set analysis exceeds its own budget, the existing exact
pair results remain valid; an output-budget failure may retain the
independently computed whole-set count, but never a truncated frontier.
No admissible completion or a partial hour yields no whole-set verdict.
The low-level set analyzer assumes its truth masks/witnesses were
generated by the validated scenario evaluator; arbitrary caller-provided
patterns are not domain evidence.

Regression: `node --test test/outcome-scenario-space.test.mjs test/outcome-scenario-sets.test.mjs test/outcome-interaction-scenarios.test.mjs`.
The generic tests include exhaustive comparison against brute force over
all 255 nonempty families of three-query truth masks.
